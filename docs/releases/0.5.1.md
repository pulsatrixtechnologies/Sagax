Sagax 0.5.1 corrige la connexion Sagax Business sur Mac quand le serveur est plus ancien que l'app, et rend le serveur plus solide au redémarrage.

## Correctifs

* **Connexion Sagax Business sur Mac** : contre un serveur plus ancien, la connexion revenait du navigateur puis échouait (« code de jumelage erroné ou expiré ») et l'app restait déconnectée. L'app ne consomme plus la connexion avant de l'utiliser : elle n'affiche l'aperçu (nom et avatar) que si le serveur le permet sans rien consommer.
* **Connexion déjà utilisée ou expirée** : l'app ne la renvoie plus jamais au serveur, même après un rechargement, et dit simplement de se reconnecter avec Sagax Business. Si le serveur a redémarré entre-temps, le message le dit.
* **Serveur, redémarrage du conteneur** : un serveur arrêté brutalement ne bloque plus son propre redémarrage (« Sagax is already using this data directory ») ; deux serveurs actifs sur le même dossier de données restent impossibles.
* **Serveur, démarrage** : la vérification des moteurs au démarrage lance au plus deux moteurs à la fois, pour éviter les pics de mémoire.
* **Windows** : le build Windows se fait sans étape manuelle (DuckDB Windows inclus d'office), et plusieurs correctifs de portabilité Windows.

## Installation

**macOS** (Apple Silicon : `arm64`, Intel : `x64`) : ouvrez `Sagax-0.5.1-arm64.dmg` ou `Sagax-0.5.1-x64.dmg` et glissez Sagax dans Applications. Signée (Developer ID) et notariée par Apple.

**Windows** (x64 et arm64) : lancez `Sagax-0.5.1-setup.exe`. Non signé : SmartScreen affiche un éditeur inconnu ; choisissez **Informations complémentaires**, puis **Exécuter quand même**. Versions portables : `Sagax-0.5.1-win-x64.zip` et `Sagax-0.5.1-win-arm64.zip`.

## English

Sagax 0.5.1 fixes Sagax Business sign-in on Mac when the server is older than the app, and makes the server sturdier on restart.

* **Sagax Business sign-in on Mac**: against an older server, the sign-in came back from the browser and then failed ("pairing code is wrong or has expired"), leaving the app signed out. The app no longer spends the sign-in before using it: it shows the preview (name and avatar) only when the server can do so without consuming anything.
* **Sign-in already used or expired**: the app never sends it to the server again, even after a reload, and simply asks you to sign in again with Sagax Business. When the server restarted in between, the message says so.
* **Server, container restart**: a server stopped abruptly no longer blocks its own restart ("Sagax is already using this data directory"); two live servers on one data folder are still impossible.
* **Server, startup**: the engine check at startup runs at most two engines at a time, to avoid memory spikes.
* **Windows**: the Windows build needs no manual step (Windows DuckDB staged automatically), plus several Windows portability fixes.

macOS builds are signed with a Developer ID and notarized by Apple. Windows (x64 and arm64, one installer) is unsigned: SmartScreen shows an unknown publisher; choose More info, then Run anyway.
