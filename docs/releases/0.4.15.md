Sagax 0.4.15 explique enfin pourquoi une routine échoue, donne à la console d'administration de l'organisation de quoi gérer le serveur, et renforce la sécurité.

## Nouveautés

* **Routines** : une exécution qui échoue dit pourquoi dans la fenêtre de la routine, avec le message du moteur au lieu d'un code brut. Un refus de Grok pour solde épuisé ou un problème de compte est nommé, avec quoi faire. Sur un serveur d'organisation, un fil épinglé sur un modèle sans accès bascule sur le modèle du bot, avec un avis.
* **Serveur d'organisation** : la console d'administration de l'organisation peut maintenant lire un journal des problèmes lisible et la fin du journal du serveur, secrets masqués. Elle peut aussi cloner, exporter et importer des bots, désactiver une personne dans Sagax (sessions coupées et routines arrêtées jusqu'à Réactiver), gérer les routines et les approbations, tester les connexions et choisir les moteurs permis.
* **Sécurité** : le test de commande réservé aux admins n'accepte plus que des exécutables connus et il est refusé sur un serveur hébergé. Les tests d'URL de fournisseur et de serveurs MCP se limitent aux entrées configurées. Les outils de test et de vérification échappent plus strictement ce qu'ils génèrent.

## Installation

**macOS** (Apple Silicon : `arm64`, Intel : `x64`) : ouvrez `Sagax-0.4.15-arm64.dmg` ou `Sagax-0.4.15-x64.dmg` et glissez Sagax dans Applications. Signée (Developer ID) et notariée par Apple.

**Windows** (x64 et arm64) : lancez `Sagax-0.4.15-setup.exe`. Non signé : SmartScreen affiche un éditeur inconnu ; choisissez **Informations complémentaires**, puis **Exécuter quand même**. Versions portables : `Sagax-0.4.15-win-x64.zip` et `Sagax-0.4.15-win-arm64.zip`.

## English

* **Routines**: a failed run says why in the routine's window, with the engine's message instead of a bare code. A Grok refusal for a used-up balance or an account problem is named, with what to do. On an organization server, a thread pinned to a model with no access falls back to the bot's model, with a notice.
* **Organization server**: the organization admin console can now read a readable problem log and the tail of the server log, with secrets masked. It can also clone, export and import bots, disable a person in Sagax (sessions cut and routines stopped until Enable), manage routines and approvals, test connections and choose the allowed engines.
* **Security**: the admin-only command test accepts known executables only and is refused on a hosted server. Provider URL tests and MCP server tests are limited to configured entries. Test and verification tooling escapes what it generates more strictly.

macOS builds are signed with a Developer ID and notarized by Apple. Windows (x64 and arm64, one installer) is unsigned: SmartScreen shows an unknown publisher; choose More info, then Run anyway.
