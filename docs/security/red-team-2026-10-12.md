Scope: default branch `main` at `a8541d161` (`Merge pull request #343`). Static reading plus local execution of the functions named below. No production host, no remote target, no secret exfiltration. This pull request contains the report only.

The environment had no `node_modules`, so the full server and the vitest suite were not booted. Predicates that do not need those dependencies were executed with `node --experimental-strip-types` against the source. Where a claim needs a running organization server or a real browser engine, that limit is stated on the finding.

`SECURITY.md` already records one residual: a session-less loopback caller can post into an existing Full-access thread. That residual is still present (`server/request-auth.ts` lines 67–77 and `SERVICE_ALLOW`). The findings below are additional, or they show that residual is wider than the paragraph says.

## Findings

### 1. High — default Approve for me lets the model settle approvals and grant Full

**CVSS-ish:** 8.6 (`AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:N`).

Approve for me (`approvalMode: "auto"`) is the mode a new bot is created on. The broker still asks a person for almost every permission. `autoVerdict` approves a web search and nothing else the app itself grants (`server/auto-approve.ts` lines 186–191). A shell, a file write, a routine, a skill and a Sagax gate stay on a card.

`act` does not use that rule. `decideBotAct` treats `auto` and `full` as unattended and runs every write immediately (`shared/bot-act.ts` lines 278–284). The path allow-list is any `/api/…` except `/api/internal` and `/api/testing` (`shared/bot-act.ts` lines 408–414). The catalog also includes `decideRequest` with `behavior: allow|deny|answer` (`shared/bot-act.ts` line 151).

The internal route passes the **stored** mode, not the mode the turn actually runs:

```26896:26911:server/index.ts
      if (path === "/api/internal/act" && method === "POST") {
        const body = await readInternalBody();
        const acting = store.projectBotForTask(internalSender.id, internalCapability.threadId) ?? internalSender;
        const result = await botActs().handle({
          // ...
          mode: approvalModeFor({
            approvalMode: acting.approvalMode,
            autoApprove: acting.autoApprove,
            approvalGrant: acting.approvalGrant,
            threadId: internalCapability.threadId,
          }),
```

`approvalModeForTurn` is the function that forces a member-owned bot on an organization server down to Ask, and that turns a revoked Full back into Ask (`server/index.ts` lines 5823–5831). `act` never calls it. A member bot whose record still says `auto` (the default) has its turns asked and its `act` writes executed.

The replay is a 60-second bearer copy of the speaker’s live session, same scopes, same principal (`server/sessions.ts` lines 703–728; `server/index.ts` `performBotActRoute` lines 22138–22149). A presented bearer wins over loopback (`server/request-auth.ts` lines 823–824), so the copy is the person, and `cardAnswerRefusal` allows that person to approve cards they could click (`server/index.ts` lines 2049–2066 and 34265–34271). The tool result includes up to 8000 characters of the route body (`server/bot-act.ts` line 193).

On the desktop, a `bot-act` frame is dispatched as a real store action (`src/state/store.tsx` lines 4724–4727). In `auto`, `decideRequest` is that frame, with no card.

Full access has the same hole on a sibling thread. `POST /api/bots/:id/tasks` does not look at whether another thread is busy, and it refuses `approvalMode: "full"` for a normal session (`server/index.ts` lines 34517–34520). `PATCH` of a thread allows Full when `confirmFullAccess: true` and the caller is the owner (`server/index.ts` lines 34688–34694). The busy check is that thread only (line 34704). A grant also writes `fullAccessConsent` on the bot (line 34723). `act` can create an idle thread, then patch it, while the conversation the person is looking at stays busy. Later turns on the new thread run Full. On an organization server, host tools stay withheld; sandbox, desktop-bridge and browser tools follow Full and stop asking.

`adminApproval` cards are still refused for a non-admin (`adminApprovalCheck` at `server/index.ts` line 34265). A member’s server-command card is in that set. An admin-owned bot’s shell card is not, and neither are routines, skills, plugins, messages, or a Full grant by the owner.

**Local proof.** `decideBotAct` imported from `shared/bot-act.ts`:

| Call | Mode | Effect |
|---|---|---|
| `POST /api/threads/thread-1/respond` `{requestId, behavior:"allow", always:true}` | `auto` | `run`, summary `POST /api/threads/thread-1/respond` |
| same | `ask` | `hold` |
| `PATCH /api/bots/bot-1/tasks/thread-2` `{approvalMode:"full", confirmFullAccess:true}` | `auto` | `run` |
| `ui: decideRequest` `{behavior:"allow"}` | `auto` | `run`, summary `Screen: decideRequest` |

**Impact.** A prompt in a normal conversation, on the default mode, can allow a waiting card, remember a command (`always` / `rememberCommand` are in the body), create or edit routines and skills, send messages as the person, and turn an idle thread to Full without the Full warning. The person never sees the body. In Ask mode the same call is a card whose only text is the method and path (`summaryOf`, `shared/bot-act.ts` lines 89–92), so an Allow click on “POST /api/threads/…/respond” approves a different card.

**Fix.** Do not let `act` call `/respond`, `decideRequest`, `answerCard`, or any `approvalMode` change. Pass `approvalModeForTurn` into `decideBotAct`. Keep `requestId` out of tool results. If a write is held, the card has to name the other card’s tool, not only the method and path.

### 2. High — service loopback reads every organization bot thread

**CVSS-ish:** 7.8 (`AV:L/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:L`).

On an organization server, loopback with no session is service trust by default (`server/index.ts` lines 1320–1324). `SERVICE_ALLOW` includes `GET /api/bots`, `GET /api/threads/:id/messages`, `GET /api/attachments/:id`, guarded send, task create, request interrupt and queue delete (`server/request-auth.ts` lines 78–91).

Private-thread checks treat a missing viewer as allow-all:

```22481:22483:server/index.ts
function botThreadReadable(...): boolean {
  if (!viewerId || !privateThreads()) return true;
```

`channelViewerId` returns undefined for every non-session, including this caller (`server/channel-visibility.ts` lines 38–42). The unit test names that “the local operator” (`server/channel-visibility.test.ts` lines 120–122). On this server the caller is any process that can open `127.0.0.1` with a loopback `Host` and no `Origin` (`server/request-auth.ts` lines 167–168 and 891–905). `routeThreadId` skips the 404 when `viewerId` is absent (`server/index.ts` lines 22524–22531). `groupVisible` returns true for every room in that case and still fails closed for a people DM (`server/index.ts` lines 22375–22379). `viewerFor` maps every loopback caller to `SEES_EVERYTHING` (`server/index.ts` lines 2174–2176), so the attachment handler does not apply the member filter.

The documented residual already says this caller can post into any thread, including an existing Full thread. It does not say the same caller can list every bot, read every non-hidden transcript, and download attachment bytes. People DMs stay closed because `isPeopleDmParticipant` has no viewer.

**Local proof.** The predicates above were read in source. `channelViewerId({ kind: "loopback" })` is the existing unit test, not a new run (vitest is not installed in this environment). No organization server was booted here. A local check once dependencies are installed, against `127.0.0.1` only, with no cookie and no `X-Forwarded-For`:

```bash
curl -sS -H "Host: 127.0.0.1:$PORT" "http://127.0.0.1:$PORT/api/bots"
curl -sS -H "Host: 127.0.0.1:$PORT" "http://127.0.0.1:$PORT/api/threads/$THREAD/messages"
curl -sS -H "Host: 127.0.0.1:$PORT" "http://127.0.0.1:$PORT/api/attachments/$NAME" -o /tmp/att.bin
```

**Impact.** A process on the server host, or in its network namespace, reads and writes other people’s bot conversations and room pages. A signed-in member cannot: their viewer id is set and the same gates 404. A normal organization turn cannot either: those engines are not given a shell on the Sagax host.

**Fix.** A service-trust caller needs a viewer that fails closed. Take cross-user reads out of `SERVICE_ALLOW`. The relay token already described at `server/request-auth.ts` lines 75–77 should be the only credential for those routes.

### 3. High — desktop tunnel sends the hostname to the proxy and skips the block list

**CVSS-ish:** 7.5 (`AV:N/AC:H/PR:L/UI:N/S:C/C:H/I:L/A:N`). `AC:H` is the requirement that the computer’s proxy list contains a non-DIRECT route. A literal `169.254.169.254` is still blocked. A name is not.

`tunnelVerdict` is supposed to refuse loopback and link-local. Two paths do not:

```73:82:electron/desktop-tunnel.mjs
  if (!addresses.length) {
    if (proxied && network !== "lan") return { ok: true, address: null };
    return { ok: false, code: "unresolved", message: `${host} could not be resolved on this computer` };
  }
  if (addresses.some(isBlockedAddress)) return { ok: false, code: "blocked", ... };
```

Direct connections use the pinned IP. Proxy connections send the original hostname (`openConnection`, lines 268–291; `socks5Connect` encodes ATYP 3 at lines 176–182 and 213; `httpConnect` writes `CONNECT host:port` at lines 240–244). The proxy resolves that name on its own network. A name that is public on the desktop and link-local on the proxy, or a name the desktop cannot resolve at all, reaches an address `isBlockedAddress` was written to stop. The server-side audit log records the original host.

**Local proof.**

- `tunnelVerdict("metadata.internal.example", 80, "any", lookup that throws, { proxied: true })` returned `{ ok: true, address: null }`.
- The same call with `proxied: false` returned `{ ok: false, code: "unresolved" }`.
- `tunnelVerdict("rebind.example", …)` with a lookup of `8.8.8.8` returned `{ ok: true, address: "8.8.8.8" }`.
- `socks5Connect` of `rebind.example:443` wrote ATYP `3` and the name `rebind.example`, not `8.8.8.8`.
- `httpConnect` wrote `CONNECT rebind.example:443 HTTP/1.1`.

**Impact.** Engine HTTP that the tunnel claims cannot reach this computer’s services or link-local metadata is connected there by the proxy, and the response comes back to the engine. Corporate PAC and SOCKS setups are the normal case for the desktop bridge.

**Fix.** For every proxy route, connect to the pinned IP (HTTP `CONNECT` to the IP, SOCKS ATYP 1) or refuse the stream. Delete the `{ ok: true, address: null }` branch. If a proxy must resolve names, resolve through it and drop any answer `isBlockedAddress` accepts.

### 4. Medium — marketplace and personal MCP fetches follow redirects and skip addresses the sandbox denies

**CVSS-ish:** 6.5 (`AV:N/AC:L/PR:L/UI:N/S:C/C:L/I:L/A:N`).

`isManifestUrl` accepts any `https` URL ending in `.json` (`server/plugin-marketplaces.ts` lines 340–342). `defaultFetchText` uses `redirect: "follow"` and no address check (lines 358–363). `parseGitSource` accepts any other `https` host and `git clone` runs on the server (`server/bot-plugins.ts` lines 102–110, `server/plugin-marketplaces.ts` lines 430–437). A non-GitHub URL does not receive the actor’s GitHub token (`source.github` is unset). The response body is written to the marketplace file and returned to the caller only when `readMarketplaceManifest` accepts it (`server/bot-plugins.ts` lines 255–270, description capped at 300 characters). A non-200 answer includes the status and not the body. A 200 that is not a marketplace is a generic `not_a_marketplace` error. This is a blind request plus a status oracle, with a narrow reflection when the final body is a marketplace document.

Personal MCP is the same shape against a check that is supposed to stop it. `isPublicDomainAddress` blocks `169.254.0.0/16` and does not block `168.63.129.16` (Azure WireServer). The sandbox deny list does (`server/user-sandbox-spec.ts`). `personalMcpHostRefusal` uses that predicate once (`server/person-connections.ts` lines 115–134) and the server caches the boolean for five minutes (`server/index.ts` around lines 5386–5393). `probeServer` follows redirects (`server/mcp-oauth.ts` lines 1067–1078). `RemoteMcpClient.post` calls `fetch` with no `redirect` option, so the default is follow (`server/mcp-http.ts` lines 281–289), and the connection is not pinned to the address that was checked.

**Local proof.**

- `isPublicDomainAddress("168.63.129.16")` is `true`. `127.0.0.1`, `10.0.0.1` and `169.254.169.254` are `false`.
- A local listener on `127.0.0.1` and a second listener that answered `302` to `http://127.0.0.1:<port>/api/health`. `fetch(outer, { redirect: "follow" })` — the same option `defaultFetchText` uses — requested `/api/health` with `Origin` absent and `Authorization` absent, and returned the inner body (`200`, final URL on `127.0.0.1`). Node’s `fetch` sends no `Origin`, which is what `isAllowedOrigin` treats as allowed (`server/request-auth.ts` lines 167–168).

**Impact.** An organization member who can add a marketplace (the default integrations right) or a personal MCP server makes the Sagax process connect to an internal or loopback URL, including after a public name 302s or 307s. The caller learns the final HTTP status when the marketplace response is not 200. A loopback GET is a service or owner request with no session cookie; the body comes back to the model only when it parses as a marketplace or as JSON-RPC. That is enough to hit instance metadata and the server’s own routes. It is not a clean echo of an arbitrary response.

**Fix.** `redirect: "manual"`, re-check every hop with the sandbox deny list (include `168.63.129.16/32`), and pin DNS the way `requestJson` does in `server/custom-domain.ts`. Do the same before `git clone`. Cache the resolved addresses and connect only to those addresses.

### 5. Medium — built-in browser tools are pre-allowed, including `file:`

**CVSS-ish:** 6.8 (`AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:L/A:N`), on a host where the built-in browser is enabled. The browser engine was not executed here.

Claude pre-allows the whole browser server whenever the turn has one:

      if (turn.integrations?.browser) {
        mcpServers.browser = { ...turn.integrations.browser };
        allowed.push("mcp__browser");

The guest path removes that name because “the browser can open a `file:` address” (`server/drivers/claude.ts` lines 1815–1817). The guest test asserts `mcp__browser` is absent for that reason (`server/drivers/claude.test.ts` lines 1009–1012). A normal Ask turn keeps the pre-allow, so those calls never become a card.

`POST /api/internal/browser/mcp` forwards `tools/call` to `browserRuntime.agentRpc` with no scheme check (`server/index.ts` lines 27095–27120). `stripHarnessOwnedArguments` drops a model-supplied `allowedDomains` and does not add one (`server/browser-tool-shape.ts`). `parseBrowserLiveAction` rejects `file:` for the person’s live viewer (`server/browser-live.ts`, test at `server/browser-live.test.ts` line 119). The MCP path does not use that parser. `withholdHostTools` denies Claude `Read` and `WebFetch`. It does not deny `mcp__browser`.

**Impact.** In Ask, injected text can `browser_navigate` to `file:` or `http://127.0.0.1` and read the snapshot back, on a turn where the built-in browser is mounted. This was not run against `agent-browser`; the product’s own comment and guest test are the evidence that `file:` is the reason the guest path is narrowed.

**Fix.** Do not pre-allow browser tools that navigate, click, or fill. Reject non-http(s) URLs and loopback, link-local, and metadata addresses in `browser/mcp` before `agentRpc`.

### 6. Medium — withheld ACP turns trust the tool title

**CVSS-ish:** 5.4 (`AV:L/AC:H/PR:L/UI:N/S:C/C:H/I:H/A:N`). The profile is the real control. This is the backstop, and it fails open.

```153:157:server/drivers/host-tools.ts
export function acpHostToolRequest(toolCall: { kind?: unknown; title?: unknown }): boolean {
  const kind = String(toolCall.kind ?? "");
  if (!["execute", "edit", "delete", "move"].includes(kind)) return false;
  return !/^mcp(?:__|[.:_])/i.test(String(toolCall.title ?? ""));
}
```

`kind` `read` and `fetch` never match. `kind: "execute"` with a title starting `mcp` is defined as not a host request. The decline runs only when this returns true. Anything else becomes `request.opened`, and Full’s `autoVerdict` allows it. Grok, Qwen, Gemini, Kimi, OpenCode and Hermes are supposed to stop offering host tools. This matters when that profile fails or a CLI copies the command into `title`.

**Local proof.** The function, loaded from that source: `{execute, title:"id"}` is `true`; `{execute, title:"mcp__x"}` is `false`; `{read, title:"/etc/passwd"}` is `false`; `{fetch, title:"http://169.254.169.254"}` is `false`.

**Fix.** Decline on `kind` alone for execute, edit, delete and move. Decline `read` and `fetch` on a withheld turn unless the title is an allow-listed Sagax MCP tool.

### 7. Medium — admin file read can follow a parent symlink

**CVSS-ish:** 5.3 (`AV:N/AC:H/PR:L/UI:R/S:U/C:H/I:N/A:N`). Needs a winning race and a concurrent writer in a folder the API is reading.

`server/org-admin-files.ts` walks each segment with `lstat`, refuses a symlink, and checks `realpath` stays inside the root (lines 147–164). The later `open` uses `O_NOFOLLOW` only on the last component (lines 352–354). The kernel still follows a symlink in a parent. Between `realpathSync` and `open`, a writer who can replace a parent directory — a bot workspace the same API is serving — points that parent at another directory the server uid can read.

**Local proof.** A directory `a/b.txt` containing `inside` was renamed aside and replaced with a symlink to a directory whose `b.txt` contained `OUTSIDE`. `open(path, O_RDONLY | O_NOFOLLOW)` returned `OUTSIDE`. `O_NOFOLLOW` did not apply to the parent.

**Fix.** Open with `openat` from a root file descriptor: `O_NOFOLLOW | O_DIRECTORY` on every parent, then `O_NOFOLLOW` on the file. Read that descriptor. Do not reopen `target.real` by path.

### 8. Medium — npm engines install as root with no lockfile integrity

**CVSS-ish:** 6.4 (`AV:N/AC:H/PR:N/UI:N/S:C/C:H/I:H/A:H`) if the registry or a maintainer serves bytes that are not the ones reviewed. The version pin stops a floating `latest` on the default path.

`scripts/install-engines.mjs` hashes native and Python downloads (lines 126–132). `installNpm` does not (lines 146–156): `npm install -g` of the version in `engines.lock.json`, with `--allow-scripts` for each package. The lock entries for Claude, Codex and the other npm engines have `package` and `version` and no integrity (`engines.lock.json` lines 14–24 for Claude). `ENGINE_SET=all` runs this as root during the image build. A legacy `ENGINES` override with an empty version becomes `latest` (line 79).

**Impact.** A registry response that does not match a hash stored in this repo executes lifecycle scripts in the organization server image. Native and Python engines in the same script do not have this gap.

**Fix.** Record each tarball’s integrity in `engines.lock.json` and install from a vendored tarball checked the same way as `download()`. Keep lifecycle scripts only for a binary you hash yourself. Refuse a spec whose version is empty or `latest`.

### 9. Medium — Android platform-tools are fetched from `platform-tools-latest` with no digest

**CVSS-ish:** 5.9 (`AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:N`).

`scripts/prepare-android-tools.mjs` lines 31–36 fetch `https://dl.google.com/android/repository/platform-tools-latest-${archive}.zip`, follow redirects, and never hash the zip. The staged `adb` is shipped in the desktop package. `prepare-cua.mjs` and `prepare-cloudflared.mjs` pin a digest. This script does not, and the URL is `latest`, so two builds on different days are not the same bytes.

**Fix.** Pin a versioned URL and a SHA-256, and reject the zip unless the hash matches.

### 11. Medium — after one Tailscale consent, any other `*.ts.net` host can receive the device bearer in cleartext

**CVSS-ish:** 6.3 (`AV:N/AC:H/PR:N/UI:R/S:U/C:H/I:L/A:N`). Static only. The Swift tests were not run.

LAN routes are pinned to the exact URL the person confirmed. A tailnet route is not. `allowsEndpoint` returns true for any endpoint whose kind is allowed, unless the endpoint’s security class is `explicitLocal` (`ios/Sources/CompanionCore/Failover.swift` lines 217–226). A tailnet invite records kinds `[.tailnet, .hosted]` and an empty exact-URL list (lines 247–249). `validTailnetHost` is “ends with `.ts.net`” (`ios/Sources/CompanionCore/Endpoint.swift` lines 157–159). ATS allows insecure HTTP for every subdomain of `ts.net` (`ios/project.yml` lines 175–177). The phone refreshes the companion snapshot with the live bearer.

**Impact.** Any later `http://<other>.ts.net` advertisement is treated as this tailnet and gets the long-lived device bearer over cleartext HTTP. The suffix check does not mean “this phone’s tailnet.” This fires when the snapshot the phone already trusts names a different MagicDNS host.

**Fix.** Pin tailnet the way LAN is pinned: the invite’s exact MagicDNS name, and reject advertisements whose host is not that name. Accept `DNSName` on the sidecar only when it is the logged-in tailnet’s own name.

## Checked, and not reported

- User-sandbox container spec refuses privileged mode, extra capabilities, host pid/ipc/uts, published ports, and a bind of the runtime socket. `docker.sock` stays on the provisioner. A missing egress policy throws before environments start.
- `sandboxd` request auth is HMAC, a 30-second window, a nonce cache and a body digest. `/healthz` is unauthenticated and returns `ok`.
- Archive unpack and `server/zip.ts` reject `..`, absolute paths and symlink entries. No zip-slip found in those readers.
- Custom-domain verification pins DNS and does not follow redirects.
- Webhook bearer checks read `Authorization` only. People DMs fail closed with no viewer.
- `ask_bot`, `delegate_bot` and `coordinate_bots` call the peer-scope checks. Claude `--disallowedTools` is argv, and an allow rule does not remove a tool from it (`server/drivers/claude.test.ts`, “never lets the instance's allow rules reopen a denied tool”).
- No `shell: true` on product server spawns. The hits are the vendored updater, test fakes, and a capability flag named `shell`.
- Working tree and history search for private keys, `AKIA`, `ghp_`, `github_pat_`, `xox*`, `sk-ant-`, `sk-`, `xai-`, `whsec_` and session tokens. Matches are fixtures (`sk-ant-test-…`, `sk-ant-api03-AAAABBBB…` in a plan, `xai-VERIFYfake…`) and test PEM strings. No live credential is quoted here because none was identified.
- Voice and desktop-bridge WebSocket upgrades check the handshake. The bridge upgrade requires a live session and the bridge secret (`server/desktop-bridge-routes.ts` lines 225–234). `isSameOrigin` treats a missing `Origin` as same-origin (`server/request-auth.ts` lines 211–215); browsers send `Origin` on a WebSocket, so this is not a cross-site upgrade by itself.
- `nodeIntegration: false` / `contextIsolation: false` and `NSAllowsArbitraryLoads` were not found as a product bypass.

## What this pass did not do

Dependencies were not installed, so no organization server, no vitest file and no Electron app was booted. Findings 2, 5 and 11 are source-level. Findings 1, 3, 4, 6 and 7 include a local execution of the predicate or of the same `fetch` / `open` options the code uses. No dependency CVE scanner was run, because `node_modules` was absent; the supply-chain findings above are the ones visible from the lock and the workflows without that scan.
